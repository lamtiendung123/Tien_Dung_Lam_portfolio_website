# Portfolio quality review

1. Inspect the actual changed text and rendered output (when available). Do not assess visuals without screenshots or a browser view.
2. Flag stock AI language, gimmicky gradients, interchangeable templates, fake architecture diagrams, fabricated project outcomes and excessive animation.
3. For every project, identify: problem, personal role, design choices, tools/platform, proof, limitations. Distinguish owner-supplied verified facts from missing evidence.
4. Check information hierarchy: technical work visible within first scroll, fast project navigation, usable on 360px phone width and keyboard.
5. Check semantic HTML, alt text, focus order, reduced motion, contrast and likely performance costs.
6. Output concise findings: BLOCKER / IMPORTANT / OPTIONAL; give file/section reference, concrete change and how to verify.
7. Never claim an audit or benchmark ran if it did not. Never replace missing project evidence with plausible numbers.

Use `docs/ANTI_SLOP.md` scoring system, with zero tolerance for unsupported claims.
